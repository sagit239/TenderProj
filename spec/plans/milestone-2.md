## 2. Database — Migration חדש

קובץ: `supabase/migrations/20261102140000_m2_tenders.sql`, מורץ ב-`npm run db:migrate` (ADR-10), ובסופו רישום ב-`app_migrations`.

### `tenders`
| עמודה | סוג | הערות |
|---|---|---|
| `id` | uuid PK | `gen_random_uuid()` |
| `name` | text not null | check: לא ריק אחרי trim |
| `department` | text not null | check: `medical` / `safety` |
| `status` | text not null default `reviewing` | check: `reviewing`, `preparing`, `not_bidding`, `submitted`, `won`, `lost` |
| `decided_at` | timestamptz null | תאריך ההחלטה "לא ניגשים" |
| `submitted_at` | timestamptz null | תאריך ההגשה |
| `created_at` | timestamptz not null default now() | |

עמודות הניתוח (`analysis_status`, `analysis_started_at`, `analysis_error`) יתווספו ב-M3, יחד עם הלוגיקה שמשתמשת בהן.

**Trigger לתאריכים** (`before update of status`), כך שהתאריכים נשמרים נכון בכל שינוי, מכל מקום:
- מעבר ל-`not_bidding` מסטטוס אחר ← `decided_at = now()`.
- מעבר לקבוצת "הוגשו" (`submitted`/`won`/`lost`) מסטטוס שמחוץ לקבוצה ← `submitted_at = now()`. מעבר בתוך הקבוצה (למשל `submitted` ← `won`) לא משנה את התאריך, וכך הוא "נשאר גם ב-won / lost". גם קפיצה ישירה ל"זכינו" שומרת תאריך הגשה.
- חזרה לרשימה הפעילה לא מוחקת תאריכים קודמים. הם פשוט לא מוצגים שם.

אינדקסים: `tenders(status)`.

### `tender_documents`
| עמודה | סוג | הערות |
|---|---|---|
| `id` | uuid PK | |
| `tender_id` | uuid not null | FK ל-`tenders`, `on delete cascade` |
| `file_name` | text not null | השם המקורי, כולל עברית |
| `storage_path` | text not null unique | `<tender_id>/<document_id>.<ext>` |
| `file_type` | text not null | check: `pdf` / `word` / `excel` |
| `created_at` | timestamptz not null default now() | מוצג כ"הועלה" |

`read_warning` ו-`analyzed_at` יתווספו ב-M3. אינדקס: `tender_documents(tender_id)`.

### RLS
בשתי הטבלאות: `enable row level security` ומדיניות `authenticated full access`, כמו ב-M1.

### Storage
- Bucket פרטי `tender-files`, נוצר ב-Migration (`insert into storage.buckets ... on conflict do nothing`), עם `file_size_limit` של 50MB ורשימת MIME מותרים: PDF, ‏doc/docx, ‏xls/xlsx.
- מדיניות על `storage.objects` ל-`authenticated` (select, insert, update, delete) רק כש-`bucket_id = 'tender-files'`.
- **שם הקובץ ב-Storage באנגלית בלבד** (`<tender_id>/<document_id>.<ext>`): Supabase Storage לא מקבל תווים בעברית בנתיב. השם המקורי נשמר ב-`file_name` ומוצג בממשק. → לתעד כ-ADR.

## 4. מסכים

### 4.1 מכרז חדש — `app/(app)/tenders/new/page.tsx` + `components/tenders/NewTenderForm.tsx`
- Breadcrumb "מכרזים פעילים ›", כותרת "מכרז חדש".
- "שם המכרז" (Placeholder "לדוגמה: אספקת ציוד רפואי"), "מחלקה" ב-Radio "רפואי" / "בטיחות" (אין ברירת מחדל, נבחר באדום).
- "מסמכי המכרז": Dropzone מקווקו — "גרירת קבצים לכאן או בחירת קבצים", והערה "PDF, Word, Excel · אפשר כמה קבצים". בנייד "בחירת קבצים" כאפשרות העיקרית. `input type=file multiple accept=...`.
- רשימת הקבצים שנבחרו: שם (LTR), גודל ו-✕. קובץ זהה (שם + גודל) לא נוסף פעמיים. קובץ בסוג לא נתמך או מעל 50MB לא נוסף, ומוצגת הודעה עם שם הקובץ.
- ולידציה (Blur וב-Submit, הודעה אדומה מתחת לשדה): "יש להזין שם למכרז", "יש לבחור מחלקה", "יש לבחור לפחות קובץ אחד" (לפי F3 ו-Flow 2: המכרז נוצר עם המסמכים שלו).
- "העלאה וניתוח" (Accent): יוצר את המכרז (`reviewing`), מעלה את הקבצים אחד אחרי השני עם חיווי "מעלה קבצים… (2 מתוך 3)", ועובר ל-`/tenders/<id>`. אם קובץ נכשל, המכרז נשמר, עוברים ללשונית "מסמכים", ומוצגת הודעת שגיאה עם שמות הקבצים שלא עלו ("אפשר להעלות אותם שוב מכאן"). אם יצירת המכרז עצמה נכשלה — הודעה בטופס, והקבצים נשארים ברשימה. הכפתור חסום בזמן השמירה (מונע יצירה כפולה).
- "ביטול" (Secondary) חוזר ל"מכרזים פעילים".
- הניתוח עצמו לא מופעל ב-M2. ב-M3 יחובר לכפתור הזה.

### 4.2 מסך מכרז — `app/(app)/tenders/[id]/page.tsx`
- Server Component שטוען את המכרז ואת המסמכים שלו. מכרז שלא קיים (או id לא תקין) ← `notFound()`, עם `not-found.tsx`: "המכרז לא נמצא" וקישור ל"מכרזים פעילים".
- פרמטרים בכתובת: `?tab=summary|timeline|tasks|issues|documents` (ברירת מחדל `summary`) ו-`?from=active|archive|submitted`. בלי `from`, הרשימה נקבעת לפי הסטטוס.
- רכיב לקוח `components/tenders/TenderView.tsx` עם:
  - **ראש מסך** (`TenderHeader.tsx`): Breadcrumb "<מכרזים פעילים / ארכיון / מכרזים שהוגשו> › <שם>" שמחזיר לרשימה (כולל לשונית המחלקה ב"הוגשו"); H1 ותגית מחלקה; Select סטטוס עם 6 האפשרויות; כפתור אייקון "⋯" (עם `aria-label` ו-Tooltip "פעולות נוספות") שפותח תפריט עם "מחיקת מכרז" באדום. בנייד: שם ותגית בשורה, הסטטוס ברוחב מלא מתחת.
  - **שינוי סטטוס:** עדכון ישיר ב-Supabase, Toast "נשמר", ואם המכרז עבר רשימה — Toast "המכרז הועבר לארכיון" / "המכרז הועבר להוגשו". נשארים במסך המכרז. בשגיאה — Toast שגיאה והסטטוס חוזר לקודם.
  - **מחיקת מכרז:** `ConfirmDeleteDialog` — "למחוק את "<שם>"?" / "יימחקו גם כל הניתוח, המשימות, התזכורות והקבצים. אי אפשר לבטל את הפעולה." ← `deleteTender` ← מעבר לרשימה שממנה נכנסו, Toast "המכרז נמחק".
  - **לשוניות:** "סיכום דרישות", "לוח זמנים", "משימות", "סעיפים בעייתיים", "מסמכים". המעבר מעדכן את `?tab=` (בלי טעינה מלאה).
  - **ארבע הלשוניות הראשונות:** כרטיס מצב ריק עם כותרת המשנה של הלשונית (למשל "סיכום דרישות המכרז") והטקסט "עדיין אין תוכן. הוא יופיע כאן אחרי ניתוח המכרז."
- **NavMenu:** בתוך מסך מכרז, הפריט הפעיל בתפריט נקבע לפי `from` (ארכיון / הוגשו / מכרזים פעילים).

### 4.3 לשונית "מסמכים" — `components/tenders/DocumentsTab.tsx`
- כותרת משנה "מסמכי המכרז", ומשמאל "העלאת מסמכים נוספים" (Secondary, פותח בחירת קבצים, אותה בדיקת סוג וגודל, חיווי בזמן ההעלאה, Toast "הקבצים הועלו" או שגיאה עם שם הקובץ).
- טבלה: קובץ (LTR) | סוג (PDF / Word / Excel) | הועלה (dd/mm/yyyy) | 🗑 (כפתור אייקון עם `aria-label` "מחיקת <קובץ>"). בנייד: כרטיס לכל קובץ.
- מחיקה: `ConfirmDeleteDialog` — "למחוק את <קובץ>?" / "הקובץ יימחק מהמכרז. תוצאות הניתוח הקיימות לא ישתנו. אי אפשר לבטל את הפעולה." ← `deleteDocument` ← רענון הרשימה, Toast "הקובץ נמחק".
- מכרז בלי קבצים: מצב ריק "אין מסמכים במכרז" וכפתור "העלאת מסמכים".

### 4.4 מכרזים פעילים — `app/(app)/tenders/page.tsx` + `components/tenders/ActiveTendersList.tsx`

## 5. נגישות ונייד (לכל המסכים)
- כל כפתור אייקון (⋯, 🗑, ✕) עם `aria-label`. תפריט "⋯" נסגר ב-Esc ובלחיצה בחוץ, והפוקוס חוזר לכפתור.
- Dropzone נגיש במקלדת (הכפתור "בחירת קבצים" הוא `label` ל-input).
- שמות קבצים ותאריכים ב-`dir="ltr"` בתוך שורה עברית.
- מתחת ל-768px: כרטיסים במקום טבלאות, לשוניות נגללות, גודל מגע 44px, בלי גלילה לרוחב.

## 6. ADRs לתיעוד ב-ARCHITECTURE.md (בזמן הבנייה)
- **ADR-13:** שמות קבצים ב-Storage לפי מזהה (`<tender_id>/<document_id>.<ext>`), והשם המקורי בטבלה.
- **ADR-14:** `decided_at` ו-`submitted_at` נקבעים ב-Trigger במעבר סטטוס, כולל קפיצה ישירה ל"זכינו" / "לא זכינו".

## 9. הנחות שנקבעו בתוכנית (לבדיקתך)
- "העלאה וניתוח" דורש לפחות קובץ אחד.
- אחרי שינוי סטטוס נשארים במסך המכרז, עם הודעה קצרה שהמכרז הועבר.
- חזרה מ"לא ניגשים" או מ"הוגש" לרשימה הפעילה אפשרית דרך בחירת הסטטוס, והתאריכים הקודמים לא נמחקים.
- "ייצוא" ו"שליחה במייל" לא מוצגים עד M6, במקום להופיע ככפתורים לא פעילים.
